# 标签打印机：只能 TSPL 直通，不要走驱动

## 结论先说

| 项目 | 情况 |
|---|---|
| Windows 打印队列名 | `EZSCAN E75`（端口 USB002，203 dpi） |
| 实际机器 | **APRT 芝润**，USB 设备名 `AY AY-D33` |
| 驱动 | **对不上**。队列名会让人以为驱动正确，其实不是 |
| 唯一可用的打印方式 | 渲染成位图 → **TSPL 指令 RAW 直发** |
| 走驱动的后果 | 指令被当文字打出来：乱码 + 不停走纸，只能清队列并给打印机**断电**才停 |

2026-09-16、09-17 各踩过一次坑：GDI（`win32ui` + `ImageWin`）、.NET `PrintDocument`、自定义
`PaperSize`、驱动预置纸张（如 `72mm x 130mm`）这几种走驱动的办法**全都不行**。

## 怎么打

```bash
python scripts/label_print.py 26 AA 1 1              # 只渲染，不打印
python scripts/label_print.py 26 AA 1 1 --print      # 打 1 张
python scripts/label_print.py 26 AA 1 10 --print     # 26AA0001 起连号 10 张
```

参数：`--w` / `--h` 标签尺寸（mm），`--printer` 队列名，`--prefix` 二维码网址前缀，
`--out` 存预览图，不加 `--print` 就只渲染不打印。

依赖：`pywin32`、`Pillow`、`reportlab`（二维码用 reportlab 自带的 qrencoder 画；本机没有
qrcode / segno，reportlab 的 renderPM 也用不了）。系统 Python 3.11 里齐全，miniforge 的
`autotest` 环境缺 reportlab。

## TSPL 作业长什么样

```
SIZE 72 mm,130 mm      ← 尺寸由指令决定，不受驱动预置限制
GAP 2 mm,0 mm          ← 间隙纸
DIRECTION 1
DENSITY 10
SPEED 4
CLS
BITMAP 0,0,<宽字节数>,<行数>,0,<位图数据>
PRINT 1,1              ← 只打一张，绝不多走纸
```

位图数据每行按字节对齐（右侧补白），**位 0 = 打黑点，位 1 = 不打**，和一般图像格式相反。

发送方式是 `win32print.StartDocPrinter(h, 1, (title, None, 'RAW'))`，`RAW` 表示数据原样交给
打印机，不经驱动渲染。

## 标签版式（业主 2026-09-17 确认）

- 尺寸 72 × 130 mm 竖版，当前装的就是这一卷。打印头宽 101.6 mm，想换小标签（如 45 × 30）
  只要 `--w 45 --h 30`，机器支持，但要先换对应的标签卷并做间距校准。
- 二维码在上、序号在下，**标签上不印网址**。
- 二维码内容是完整网址，例如 `https://www.soaipower.com/t/26AA00019`。
- 二维码按模块整数倍作图并留 4 格静区，避免缩放糊边扫不出。

## 号码从哪来

成品码 = 年 2 位 + 代次 2 字母 + 流水 4 位 + Damm 校验 1 位，例如 `26AA00019`。
代次由 ERP 的「开委外生成单」统一发放，一张委外单一批号码，不要手工编号，否则会和系统发的撞号。
校验位算法与工位软件 `backend/finished_code.py`、SOAI 后端 `ww_order_api.py`、
前端 `serialCode.ts` 是同一套，改一处就要改全部。

## 出问题时

1. 先清队列：`Get-PrintJob -PrinterName 'EZSCAN E75' | Remove-PrintJob`。
2. 机器里可能还存着没吐完的数据，**断电再上电**才会清干净。
3. 再打之前，确认用的是本脚本（TSPL 直通），不是任何走驱动的方式。
